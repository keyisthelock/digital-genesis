# Homer Autobiographical Transfer

The same two route-entry tiles use equal movement costs. Each has an arbitrary observable color. A hidden assignment schedules a 12-energy loss after two to four ticks on one color. The map generator, side and risky color vary with the seed. The transfer layout changes road geometry and cue placement while retaining the color-to-consequence relationship. No ground-truth assignment enters the model input.

Experience is recorded by the same SQLite journal used by Homer 1.7. A delayed loss links to the actual first route-entry event. The hybrid receives bounded, attributed observations from its journal. The memory-disabled arm still records observations and gets the same current observation and action mask. The no-prior transfer arm begins with an empty life apart from activation. Hybrid motor state resets to the same frozen start in each evaluation. Only the native repeated condition carries spatial and recurrent motor state forward.

On pilot seed 17100, the source run entered the blue road and incurred no delayed loss. The memory-enabled model retrieved the observed blue entry. In both the repeated and changed layouts, it chose the amber road and lost 12 energy. The memory-disabled and no-prior comparisons made the same tested choice where present. A recorded entry without a loss statement is weaker evidence than a recorded loss. This is why the follow-up separately samples an observed adverse encounter.

The exploratory seed 17201 was selected after inspecting native exposure results, as the first seed with a recorded penalty. In both the repeated and new layouts, the memory-enabled hybrid received two actual records: the blue entry and the subsequent 12-energy loss. It chose blue anyway and lost 12 energy again. The memory-disabled model made the same choice in both layouts. The no-prior transfer control also chose blue. This follow-up tests whether adverse recall can reach the model and change its action. It does not estimate a population-wide memory effect. Inspect the retrieved IDs and original SQLite events under output/loss_followup.
