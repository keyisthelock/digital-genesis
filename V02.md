# Digital Genesis v0.2

Incremental mechanics on the existing world, UI and local policy. No dependencies
added, no internet access. Original experiments and ancestor memorials are retained.

## Run

```powershell
python main.py --resource-fraction 0.35 --max-population 100 --maturity-age 100
python main.py --headless --generations 20 --seed 42 --baseline
python main.py --legacy-generations
python experiment.py --output results/my_comparison --ticks 1200 --duty 0.25
python experiment.py --output results/my_overnight --ticks 10000000 --hours 6 --duty 0.15 --population 30 --max-population 100 --resource-fraction 0.35 --max-lifespan 3000 --maturity-age 100
```

Use a new output directory for each comparison. `Run Simulation.ps1` launches the
updated visual version with the already installed local Python/Pygame. Existing
open windows continue using their old code until closed; they are not modified.

## Mechanics

- Resource fraction [0,1] scales initial food and daylight-dependent regeneration.
  Zero yields no food and produces starvation without forced deaths.
- Lifetime mode is the main program default. The `Simulation` API retains legacy
  defaults for compatibility with existing tests and callers.
- Juveniles grow from 35% to 100% size over the maturity age, with a small extra
  growth energy cost. Visual radius reflects size. All founders start juvenile.
- Mature organisms with at least 85 energy can reproduce every 60 ticks. The parent
  pays 40 energy; the child receives 30, so reproduction cannot create energy.
  Offspring start at their parent's location, with fresh memory, new IDs, and
  mutated inherited genomes. Offspring generation is parent generation + 1.
- Living population is capped. Dead organisms are archived and removed from RAM;
  population replacement/resurrection does not occur in lifetime mode. Extinction
  is allowed. Logging windows (400 ticks) retain the UI's generation counter, but
  do not replace the population. Ancestry snapshots may repeat an ID at boundaries;
  deaths have an explicit cause and world tick. `births.jsonl` records new children.
- Baseline uses the same lifetime rules, food and costs, but every genome is the
  original fixed genome and mutation is disabled. No fitness-based selection is
  called in either lifetime treatment. Differential ecological survival and births
  still exist; the baseline removes heritable variation, not survival pressure.

## Paired experiments

`experiment.py` runs evolving and baseline treatments for seeds 0–9. Every run
loads the exact same saved `results/v02_terrain.json`, including initial food;
its SHA-256 is recorded. Both members of each pair start from the same RNG seed,
initial positions, energy and juvenile ages. Each owns independent world resources.
Mutation changes random-number consumption after births, so trajectories then
diverge; seeds are paired, not identical random draws at every later decision.

`comparison.csv` contains 20 rows. `paired_summary.csv` contains means, paired
differences and their sample standard deviations (not significance tests).
`history.csv` retains 100-tick snapshots. Outputs refresh atomically for summary
CSVs; individual logs flush at checkpoints. `experiment.json` records parameters,
progress, status and termination reason. Individual run configs and ancestry are
preserved. Long-run memory is bounded by living population and world size; disk
logs grow with births and logging windows.

Metrics: survivors and survival fraction count those alive at the observation
horizon; founder survival only counts original founders. Organism-ticks sum all
ticks lived; average observed lifespan divides these by all organisms born and
includes right-censored living ages. Food consumed includes food removed even if
some is wasted at the energy cap. Food efficiency is organism-ticks per unit of
food consumed (blank if zero), not biochemical conversion efficiency: founding
energy and reproduction costs confound this descriptive ratio. Average fitness
is the existing age/food/exploration formula averaged over all organisms ever born,
including archived dead organisms and censored survivors.

Six-hour runs are wall-time limited and throttled to an approximate CPU duty
fraction, not a hard OS resource cap. All treatments advance in equal 25-tick
batches. Runs can terminate early if every population goes extinct or the tick
limit is reached. A window being open does not mean ticks are advancing. Prevent
Windows sleep if you want six continuous hours; elapsed wall time includes sleep.
The manifest distinguishes completion, extinction and failures. There is no
automatic population rescue, and no checkpoint/resume in v0.2.

This is simplified asexual artificial life, not a biological amoeba model. It does
not establish consciousness, open-ended evolution, or guaranteed improvement.
